Threshold — Privacy Policy

Last updated 2026-08-31 · applies to Threshold for iOS and Android (com.gapfound.threshold)

Threshold collects no data and shares no data. There is no account, no server and no analytics. Everything you record stays encrypted on your own phone.

This page is generated directly from the app's data inventory, which is kept in the source repository and updated in the same commit as any change to how the app handles data. What follows is that inventory, unedited.

Status: no data collected, no data shared. That statement is literally true, not a marketing position. There is no server to collect anything to.

What leaves the device

Nothing. Threshold has no backend, no account system, no login, no sync, and no analytics. The app makes no network requests of its own.

The only outbound traffic the binary is capable of comes from the platform subscription SDK (RevenueCat), which talks to RevenueCat and the platform store to answer one question: is this install's subscription active. It is given an anonymous store-generated identifier and no owner data — no dog name, no encounters, no email, no device identifier we set.

The 256-bit document key is generated on the device on first launch, held in expo-secure-store with WHEN_UNLOCKED_THIS_DEVICE_ONLY, and never transmitted. Every write draws a fresh random 96-bit nonce.

Owner-initiated export

Two things can leave the device, both only when the owner chooses:

  1. An encrypted backup file, protected by a passphrase the owner sets (scrypt N=2^15 → AES-256-GCM). Handed to the OS share sheet. We never see it, and we cannot open it — losing the passphrase means losing the file.
  2. A PDF report, generated on the device and handed to the share sheet, for the owner to send to their trainer, behaviourist or vet.

Permissions

Verified against the generated AndroidManifest.xml, not just the config. Only these two are present in a build:

PermissionWhyUser-facing
INTERNETThe subscription SDK asking the store whether this install is subscribed. Nothing else makes a network request.No prompt; not shown by Android
READ_EXTERNAL_STORAGE (max SDK 32)Reading a photo the owner chose to attachPrompted, and declinable — the app works fully without it

Explicitly stripped via blockedPermissions, because the libraries we depend on would otherwise add them by default:

ACCESS_FINE_LOCATION, ACCESS_COARSE_LOCATION, RECORD_AUDIO, SYSTEM_ALERT_WINDOW, WRITE_EXTERNAL_STORAGE, VIBRATE, CAMERA

CAMERA is contributed by expo-image-picker. The app only ever opens the photo library, never the camera, so it is removed and the iOS camera usage string is not declared either.

A few normal-level permissions arrive from transitive Android libraries rather than from our configuration - ACCESS_NETWORK_STATE, and the biometric pair USE_BIOMETRIC / USE_FINGERPRINT that comes with the OS keystore integration behind expo-secure-store. None is a runtime-prompted permission, none grants access to personal data, and none is used to collect anything.

No location, no microphone, no contacts, no camera roll scanning, no background access, no notifications, no draw-over-other-apps.

On iOS the only permission string declared is NSPhotoLibraryUsageDescription. The config plugins would otherwise add NSCameraUsageDescription, NSMicrophoneUsageDescription and NSFaceIDUsageDescription by default, so each is explicitly disabled (cameraPermission: false, microphonePermission: false, faceIDPermission: false), which deletes the key rather than leaving a prompt the app would never show. The app never opens the camera, never records audio, and never gates the keystore behind biometrics.

Updates, and what survives

An app update replaces the code, never the stored data. The key alias (threshold.document.key.v1) and the filename (threshold.enc) are fixed, the envelope format is unchanged, and nothing in the startup path deletes anything - erasing is reachable only from the owner tapping "Erase all data on this device". Tests cover a document written by one version being read whole by the next, including fields a newer version added.

What DOES lose records, by design:

  • Deleting the app. The container goes with it.
  • Restoring the phone from a backup. The document key is stored WHEN_UNLOCKED_THIS_DEVICE_ONLY, so it is deliberately excluded from iCloud and iTunes backups and never leaves the device. A restored copy of the encrypted file has no key to open it. On Android the same holds: the expo-secure-store backup rules keep the keystore entry out of auto-backup, so a restored file cannot be opened either.
  • Moving to a new phone.

That is the cost of the privacy promise: because we hold no copy and the key never leaves the device, only the owner's own encrypted export can move records between installs. Onboarding says so on first launch, and it is the reason export exists.

Not present in this app

  • No analytics SDK (no Firebase, Amplitude, Segment, Mixpanel, or equivalent)
  • No crash reporting (no Sentry, Crashlytics, Bugsnag)
  • No advertising SDK, no ad identifiers, no attribution SDK
  • No tracking as defined by Apple's App Tracking Transparency — the app never presents the ATT prompt because it has nothing to ask for
  • No third-party fonts, tag managers or remote configuration
  • No Play Integrity API and no App Attest. Both exist so a server can refuse requests from tampered clients. There is no server, so they would protect nothing and would add a dependency for show.

Store form answers

Apple — App Privacy: Data Not Collected. PrivacyInfo.xcprivacy declares NSPrivacyTracking: false, no tracking domains, no collected data types, and required-reason API declarations only (file timestamp C617.1, disk space E174.1, user defaults CA92.1).

Google Play — Data safety: "No data collected" and "No data shared". Data is encrypted at rest. There is no account, therefore no account deletion flow is required; Settings offers "Erase all data on this device", which deletes every record and destroys the encryption key.

Account deletion

There are no accounts, so there is nothing to delete server-side. In-app, Settings → Erase all data on this device removes every encounter, photo and setting and destroys the document key. It cannot be undone and we hold no copy.

Age rating

18+ / adults only. The app is aimed at dog owners managing a behaviour programme. It contains no user-generated content sharing, no social features, no chat, and no purchasable content other than the subscription.
